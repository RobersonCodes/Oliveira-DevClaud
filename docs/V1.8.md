# Oliveira DevCloud v1.8 — Repository Map & Incremental Cache

A v1.8 transforma a Repository Intelligence em um recurso reutilizável pelo control plane e adiciona cache persistente por commit SHA para checkouts limpos.

## Cache incremental

Antes de executar a análise completa, o backend consulta a revisão Git do workspace (`HEAD`, branch e `git status`).

- **worktree limpo + SHA já conhecido:** retorna `RepositorySnapshot` do PostgreSQL;
- **worktree limpo + SHA novo:** reanalisa e grava um snapshot para aquele commit;
- **worktree com alterações locais:** ignora o cache e reanalisa, evitando servir contexto obsoleto;
- **refresh explícito:** força nova análise e atualiza o snapshot do SHA atual.

O cache é isolado por `workspaceId + commitSha`.

## Repository Map

Novo frontend:

```text
/repository-map?workspaceId=<id>
```

A tela apresenta:

- árvore de diretórios/arquivos;
- classificação visual de source, test, route, manifest, config e infra;
- branch e SHA atuais;
- estado clean/dirty;
- manifests e sinais de arquitetura;
- contadores de source/tests/routes;
- estado do cache (HIT/MISS/DIRTY_WORKTREE/FORCED_REFRESH).

## API

```text
GET    /api/v1/repository-intelligence/:workspaceId
GET    /api/v1/repository-intelligence/:workspaceId?refresh=true
DELETE /api/v1/repository-intelligence/:workspaceId/cache
```

A remoção manual do cache exige `ADMIN` ou `OWNER`.

## Segurança

- `.env` e `.env.*` são excluídos do mapa;
- `.git`, `node_modules`, builds e coverage continuam ignorados;
- o mapa permanece limitado a 400 arquivos;
- snapshots só são reaproveitados quando o Git informa worktree limpo;
- nenhum conteúdo arbitrário de arquivos é persistido no snapshot além do resumo já produzido pela Repository Intelligence.

## Integração com Command Center

O Command Center agora usa o mesmo serviço de cache. Planejamentos repetidos sobre o mesmo commit limpo deixam de repetir a varredura completa do repositório.

O `AuditLog` registra cache hit/miss e o motivo da decisão.
