# Oliveira DevCloud v2.2 — Dependency-Aware Task Routing

A v2.2 adiciona uma camada entre o Task Context Router e o Orchestrator para decidir quando tarefas de agentes podem executar em paralelo e quando existe uma dependência arquitetural forte.

## Novo pacote

`@oliveira/dependency-router`

O router recebe o DAG já validado e os contextos individuais de Codex/Claude. Ele procura sinais controlados de dependência:

- contrato de API consumidor/produtor;
- relações locais entre módulos priorizados;
- domínio compartilhado com intenção explícita de integração;
- endpoints backend relacionados ao domínio da tarefa frontend.

O algoritmo é conservador: se não houver evidência forte, mantém paralelismo. Dependências existentes nunca são removidas e uma nova dependência só é aplicada se não criar ciclo no DAG.

## Exemplo

```text
CODEX · backend
POST /checkout
CheckoutService
        ↓
contrato de API detectado
        ↓
CLAUDE · frontend
CheckoutPage
useCheckout
```

Nesse caso a etapa de frontend pode receber `dependsOn: [codex-implementation]` automaticamente. Para tarefas independentes, o DevCloud registra que o par pode continuar em paralelo.

## Auditoria e transparência

Cada decisão contém `kind`, `confidence` e `reason`. O Command Center mostra essas informações antes do usuário iniciar a equipe, e o `taskContext` persistido em `OrchestrationStep` guarda os motivos e os pares paralelos.

## Segurança

O Dependency Router não lê novos arquivos, não executa comandos e não amplia acesso ao filesystem. Ele trabalha somente sobre o plano validado e os mapas previamente filtrados por Repository Intelligence / Code Intelligence. O DAG é validado novamente depois do roteamento.
