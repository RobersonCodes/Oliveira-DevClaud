# Oliveira DevCloud v2.1 — Agent Task Context Router

A v2.1 separa o contexto entregue a cada agente depois que o plano é validado.

## Fluxo

1. Repository Intelligence e Code Intelligence produzem o mapa seguro do workspace.
2. Focused Context seleciona os elementos mais relacionados ao objetivo.
3. O planner gera o DAG e o Policy Engine valida o plano.
4. O `@oliveira/task-context-router` examina cada etapa AGENT.
5. Codex recebe prioridade para API, services, repositories, database, models, endpoints e testes de backend.
6. Claude recebe prioridade para páginas, componentes, hooks, UI, estilos e testes de frontend.
7. O contexto roteado é persistido em `OrchestrationStep.taskContext` e anexado ao prompt somente depois da validação do plano.

## Segurança

O router não lê novos arquivos, não acessa secrets e não expande o escopo do Repository/Code Intelligence. Ele apenas reorganiza o contexto já filtrado. O prompt deixa explícito que o mapa é uma prioridade inicial e deve ser confirmado no repositório antes de alterações.

## Limites por tarefa

- até 10 arquivos prioritários;
- até 12 símbolos;
- até 8 endpoints para Codex;
- até 14 relações locais;
- até 6 hints arquiteturais.

## Persistência

Migration adicionada:

`OrchestrationStep.taskContext JSONB`

Isso permite auditoria e inspeção posterior do contexto efetivamente entregue a cada agente.
