# Oliveira DevCloud v1.3 — Async Provisioning

Provisionamento pesado saiu da requisição HTTP e passou para BullMQ/Redis + worker.

## Fluxo
1. API cria `SetupJob` e retorna HTTP 202.
2. Worker consome `oliveira-setup`.
3. Progresso é persistido em PostgreSQL por estágio.
4. UI consulta `/api/v1/setup/jobs/:jobId` e exibe percentual/etapa.
5. Fechar o navegador não cancela o provisionamento.

## Estágios
QUEUED → CLONING_REPOSITORY → DETECTING_STACK → INSTALLING_DEPS → CONFIGURING_PORTS → STARTING_IDE → READY/FAILED.

## Segurança/confiabilidade
- Jobs vinculados a organization/workspace.
- Leitura de status exige membership.
- Somente um setup QUEUED/RUNNING por workspace.
- Erros ficam persistidos sem devolver secrets.
- Concorrência do setup worker limitada a 2.
