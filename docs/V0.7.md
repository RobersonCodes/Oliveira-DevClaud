# Oliveira DevCloud v0.7 — Multi-Agent Git Isolation

A v0.7 impede Codex e Claude Code de escreverem diretamente sobre o mesmo checkout.

## Fluxo

1. Uma `AgentTask` é criada.
2. O `git-engine` captura o `HEAD` atual como `baseCommit`.
3. É criada uma branch `agent/{codex|claude}/{taskId}`.
4. É criado um Git Worktree em `/workspace/worktrees/{taskId}`.
5. O agente inicia via tmux com `cwd` apontando para esse worktree.
6. O usuário revisa logs e diferenças pela API/UI.
7. Em `Merge`, alterações não commitadas recebem um snapshot controlado e são mescladas com `--no-ff` somente se o checkout principal estiver limpo.
8. Em `Reject`, worktree e branch isolados são removidos.

## Segurança e integridade

- IDs e nomes de agentes são validados antes de compor paths/branches.
- Operações Git usam arrays de argumentos via Docker Exec; prompts não entram em comandos Git.
- Merge é bloqueado se o agente ainda estiver rodando.
- Merge é bloqueado se o worktree principal estiver sujo.
- `Merge` e `Reject` são ações explícitas e auditadas.
- Diffs são limitados no backend para evitar respostas gigantes.

## API

- `GET /api/v1/agents/:taskId/changes`
- `POST /api/v1/agents/:taskId/merge`
- `POST /api/v1/agents/:taskId/reject`

## Banco

`AgentTask` agora guarda:

- `branchName`
- `worktreePath`
- `baseCommit`
- `reviewStatus`
- `mergeCommit`
- `mergedAt`
- `rejectedAt`
