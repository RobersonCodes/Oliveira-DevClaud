# Oliveira DevCloud v2.0 — Focused Context Intelligence

A v2.0 conecta Repository Intelligence e Code Intelligence diretamente ao AI Command Center. O objetivo é evitar que o planner receba um mapa genérico demais ou o repositório inteiro.

## Novo pacote

`@oliveira/context-engine`

Ele recebe o objetivo do usuário e o `CodeIntelligence` já cacheado, extrai termos relevantes, pontua símbolos/endpoints/arquivos e expande o contexto por dependências locais de um salto.

Limites deliberados:

- até 24 símbolos priorizados;
- até 12 endpoints;
- até 18 arquivos focados;
- até 24 relações locais;
- nenhuma leitura adicional de `.env`, secrets ou código bruto;
- fallback arquitetural pequeno quando não há match lexical.

## Fluxo

```text
Objetivo do usuário
      ↓
Repository Intelligence
      ↓
Code Intelligence (cache SHA)
      ↓
Focused Context Engine
      ├── termos do objetivo
      ├── símbolos relevantes
      ├── endpoints relacionados
      ├── arquivos priorizados
      └── dependências locais (1 hop)
      ↓
AI Planner / deterministic fallback
      ↓
Policy Engine
      ↓
Orchestration
```

## Endpoint de inspeção

```text
GET /api/v1/context-intelligence/:workspaceId?objective=<texto>
```

Use `&refresh=true` para forçar a atualização dos caches estruturais e semânticos antes da seleção focada.

O endpoint exige papel `DEVELOPER` ou superior no tenant do workspace.

## Command Center

O `POST /api/v1/command-center/plan` agora persiste em `repositoryContext.code`:

- `objectiveTerms`;
- `files`;
- `symbols`;
- `endpoints`;
- `edges`;
- métricas de seleção.

O planner determinístico também usa os arquivos e símbolos priorizados em seus prompts, e o planner de IA recebe o mesmo contexto estruturado.

## Segurança

A v2.0 não transforma o planner em um buscador irrestrito de arquivos. O Context Engine opera somente sobre o mapa já filtrado pelo Repository/Code Intelligence. Nenhum conteúdo de segredo é incluído e os comandos `SYSTEM` continuam limitados pela allow-list do Policy Engine.

## Limitações conhecidas

A pontuação ainda é lexical/heurística. Ela não substitui embeddings, AST completa, Language Server ou análise de fluxo de dados. A expansão de dependências é deliberadamente rasa para manter previsibilidade e custo de contexto baixo.
